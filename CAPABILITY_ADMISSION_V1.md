# MatVerse Capability Admission v1

Protocol: `matverse.capability-admission.v1`

## Purpose

The organism is defined operationally as governed information plus admitted capabilities. A capability is therefore not admitted because it exists in a UI, appears in a prompt, is discoverable from a provider, or was generated by another skill.

Canonical set:

`Capability = Skill ∪ Nucleus ∪ Model ∪ Runtime ∪ Tool ∪ HumanAuthority`

Fail-closed admission:

`AdmittedCapability = Capability ∧ Contract ∧ Authority ∧ Evidence`

For executable capabilities the implementation additionally requires:

`Implementation ∧ Test`

Therefore:

`DISCOVERED != IMPLEMENTED != TESTED != ADMITTED`

## Lifecycle

- `DISCOVERED`: observed in a host, corpus, repository or provider.
- `SPECIFIED`: contract exists, but implementation evidence may not.
- `IMPLEMENTED`: implementation reference exists, but testing/admission is incomplete.
- `TESTED`: implementation has test evidence, but authority/evidence admission can still be incomplete.
- `ADMITTED`: all required admission references are present and the capability is not blocked/superseded.
- `HOLD`: admission requirements are incomplete.
- `BLOCKED`: governance prevents use.
- `SUPERSEDED`: retained for lineage but not admitted for new execution.

## No-Left-Behind integration

Every capability can emit a `SweepObservation` into the `CoverageRegistry` using the stable identity:

`capability://<capability_id>`

Changing its contract, implementation, evidence or lifecycle changes the content hash while preserving the same object identity. That causes the coverage layer to treat the capability as a revised object rather than inventing a second capability.

## Host-discovered capability inventory

The following capabilities were observed through the host UI and are intentionally initialized as `DISCOVERED`, not as implementation proof:

| Capability | Class | Intended role |
|---|---|---|
| `experiment-design-gate` | SCIENTIFIC_GATE | reject tautological/non-falsifiable experimental designs |
| `external-reproduction-kit` | EXTERNAL_REPRODUCTION | prepare/validate independent clean-room reproduction kits |
| `mechanism-binding-audit` | MECHANISM_BINDING | prove tested mechanism is bound to the executed mechanism |
| `sovereign-installer-guard` | SOVEREIGN_SECURITY | reject blind pipe-to-shell installation and require inspection/provenance |
| `Word Documents` | ARTIFACT | DOCX artifact capability |
| `PDFs` | ARTIFACT | PDF artifact capability |
| `Presentations` | ARTIFACT | PPTX artifact capability |
| `Spreadsheets` | ARTIFACT | XLSX/CSV artifact capability |
| `Skill Creator` | META | propose new skills/capabilities |

A host observation proves availability/visibility only. It does not prove that the repository contains the implementation, that the capability has passed tests, or that the organism has admitted it.

## Scientific closure chain

The three research-specific skills form a useful closure chain, but each still needs independent admission:

`Hypothesis -> experiment-design-gate -> falsifiable experiment -> mechanism-binding-audit -> executed/evidenced mechanism -> external-reproduction-kit -> independent reproduction candidate`

This chain must not be used to auto-promote `EXTERNAL_PASS`; external evidence and the relevant MatVerse gate remain required.

## Skill Creator invariant

`SkillCreated != SkillAdmitted`

A skill proposed or generated by `Skill Creator` enters as a candidate. It still requires contract, implementation, tests, evidence and authority before admission.

## Sovereign installer invariant

`curl | bash`, `wget | sh`, and equivalent blind pipe-to-shell patterns must be treated as uninspected remote execution. A sovereign installer capability may propose inspection, hashing and provenance validation, but only the governing authority may admit execution.

## Evidence boundary

The capability catalog records what the system knows about a capability. It does not transform a host label into evidence of implementation. Missing implementation/test/evidence/authority references yield `HOLD`.
